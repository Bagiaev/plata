# Plata Quote Service

HTTP-сервис на Go для асинхронного обновления валютных курсов. Поддерживает пары из USD, EUR и MXN.

## Запуск через Docker Compose

```bash
docker compose up --build
```

Compose запускает PostgreSQL, применяет миграции и поднимает API на `http://localhost:8080`. Для остановки используйте `docker compose down`.

## Локальный запуск

Понадобятся Go 1.25.3 или новее и PostgreSQL с созданной базой данных. Укажите в `DATABASE_URL` параметры подключения к своей базе.

```bash
export DATABASE_URL='postgres://USER:PASSWORD@localhost:5432/DB_NAME?sslmode=disable'
go run ./cmd/migrate
go run ./cmd/server
```

В PowerShell задайте переменную через `$env:DATABASE_URL = 'postgres://...'`, затем выполните те же команды `go run`. Для сборки используйте `go build ./...`.

Миграции лежат в [migrations/](migrations/) и встраиваются в `cmd/migrate`. Повторный запуск применяет только новые миграции.

При обновлении с первой версии остановите старый сервер и запустите миграции перед новым сервером. Миграция сохранит результаты и вернёт незавершённые заявки в очередь.

## API

Полный контракт запросов и ответов описан в [OpenAPI](docs/openapi.yaml). Файл можно открыть в Swagger Editor.

### Поставить обновление в очередь

```bash
curl -i -X POST http://localhost:8080/api/v1/quotes/updates \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: eur-mxn-demo-1' \
  -d '{"base_currency":"EUR","quote_currency":"MXN"}'
```

Сервис отвечает `202 Accepted` с `update_id` и статусом. Новый запрос получает статус `pending`. Повтор с тем же ключом и парой получает исходный ID и текущий статус. Тот же ключ с другой парой возвращает `409 Conflict`. Каждый запрос без ключа создаёт отдельное обновление.

### Проверить статус и результат

Подставьте UUID из ответа POST.

```bash
curl http://localhost:8080/api/v1/quotes/updates/UPDATE_ID
```

Заявка остаётся `pending`, пока воркер получает курс. В статусе `completed` доступны дата и курс в виде десятичной строки, например `"20.123456789"`. При `failed` поле `error` содержит публичное сообщение.

### Получить последнее успешное значение

```bash
curl 'http://localhost:8080/api/v1/quotes/latest?base=EUR&quote=MXN'
```

Сервис выбирает курс с самой свежей датой источника. При совпадении дат используется последний сохранённый результат. До первого успешного обновления для пары этот маршрут возвращает `404`.

`GET /health/live` проверяет, отвечает ли процесс. `GET /health/ready` проверяет соединение с PostgreSQL.

## Источник курса

Сервис использует `GET /v2/rate/{base}/{quote}` из [Frankfurter v2](https://frankfurter.dev/). Публичный API работает без ключа и ограничивает частоту запросов. Frankfurter публикует справочные курсы по расписанию источников данных. Поле `updated_at` содержит дату курса в формате RFC 3339 с временем `00:00:00Z`. Если в ответе источника нет даты, используется время получения курса в UTC.

## Фоновая очередь

HTTP API и один воркер работают в одном процессе. PostgreSQL хранит заявки и результаты в таблице `quote_updates`. Воркер читает самую старую заявку в статусе `pending`, запрашивает курс и записывает результат. При пустой очереди он ждёт 500 мс.

При ошибке источника заявка получает статус `failed`. Чтобы запросить курс ещё раз, создайте новую заявку. Если процесс остановится до записи результата, заявка останется `pending` и продолжит обрабатываться после запуска. Запускайте один экземпляр сервиса на базу данных, чтобы заявки обрабатывались последовательно.

## Настройки

Приложение читает переменные окружения.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | обязательна | Строка подключения к PostgreSQL |
| `HTTP_ADDR` | `:8080` | Адрес HTTP-сервера |
| `EXCHANGE_API_BASE_URL` | `https://api.frankfurter.dev/v2` | Базовый URL провайдера |
| `EXCHANGE_API_TIMEOUT` | `5s` | Таймаут запроса курса |
